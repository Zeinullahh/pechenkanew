# Silence AI

## Руководство пользователя Server Security

Инструкции для конечных пользователей по регистрации, установке, защищенному доступу, мониторингу безопасности и управлению политиками.

> **ДОКУМЕНТАЦИЯ ДЛЯ КЛИЕНТОВ**
> Используйте это руководство для регистрации сервисов, установки нативной версии Server Security, настройки управления доступом, анализа инцидентов и мониторинга защиты серверов.

Версия 1.0 • октябрь 2026 г.

# Как пользоваться этим руководством

Это руководство предназначено для администраторов и уполномоченных операторов Silence AI Server Security. В нем рассматриваются действия, доступные в клиентском интерфейсе, и проверки, которые необходимо выполнить, прежде чем полагаться на изменение защиты или управления доступом.

> **Важный принцип эксплуатации**
> Регистрация, установка пакета, регистрация сервера в системе, настройка политик и активная защита — отдельные этапы. Если параметр отмечен как ожидающий, не полагайтесь на него, пока панель не сообщит об активации.

# 1. Перед началом работы

Перед началом работы подготовьте следующие сведения и права доступа:

- Учетную запись Silence AI с доступом к Server Security.
- Домен сервиса или имя сервера, который планируется зарегистрировать.

- Сетевое подключение целевого сервера к Silence AI.
- Права администратора на целевом сервере Linux для нативной установки.

- Для регистрации Hosted: IP-адрес назначения и разрешение на изменение веб-сайта и DNS.
- Для регистрации Self-Hosted: URL вышестоящего сервиса и утвержденную в организации процедуру развертывания.

| **Поддерживаемая нативная цель**       | **Пакет** |
|----------------------------------------|-----------|
| Ubuntu Server 22.04 или 24.04 LTS, amd64 | DEB     |
| Fedora Server 44, x86_64               | RPM       |

> **Оплата Hosted**
> Защита трафика Hosted оплачивается по фактическому использованию. Прежде чем полагаться на нее, убедитесь, что на счете достаточно средств.

# 2. Вход и открытие Server Security

1.  Откройте панель администрирования Silence AI и выберите Log in.

2.  Пройдите MFA учетной записи, используя текущий шестизначный код приложения-аутентификатора.

3.  Откройте Server Security, затем выберите Servers.

В каждой строке сервера могут быть доступны действия Install, Setup / recovery и Open Security. Доступное действие зависит от текущего состояния регистрации сервера.

# 3. Регистрация сервиса

## 3.1 Выбор Hosted или Self-Hosted

| **Тип развертывания** | **Когда использовать**                                 | **Обязательные поля** |
|-----------------------|--------------------------------------------------------|-----------------------|
| Hosted                | Трафик будет защищен с помощью сервиса Hosted.          | Domain + IP Address   |
| Self-Hosted           | Сервис работает в вашей среде.                          | Domain + Upstream URL |

> **Регистрация — не установка**
> Создание записи сервиса Hosted или Self-Hosted не устанавливает нативный пакет Server Security и не регистрирует сервер Linux в системе.

## 3.2 Создание записи сервиса

4.  Выберите Register new agent.

5.  Выберите Hosted или Self-Hosted и перейдите к этапу ввода данных агента.

6.  В поле Domain укажите только имя хоста, без пути URL.

7.  Для Hosted введите IP Address. Для Self-Hosted введите Upstream URL.

8.  Выберите Register.

## 3.3 Hosted: подтверждение владения и маршрутизация трафика

В процессе регистрации отображаются два отдельных элемента: метатег веб-сайта для подтверждения владения и A-запись для маршрутизации трафика Hosted.

9.  Добавьте предоставленный метатег внутрь HTML-элемента \<head\> веб-сайта.

10. Опубликуйте изменение и убедитесь, что веб-сайт общедоступен по зарегистрированному домену.

11. В диалоговом окне регистрации выберите Verify Domain Ownership и убедитесь, что появилось сообщение Verification successful!.

12. Добавьте отображаемую A-запись в DNS для маршрутизации трафика Hosted.

13. После распространения DNS убедитесь, что веб-сайт по-прежнему доступен по нужному домену.

> **Если подтверждение не удалось**
> Проверьте написание домена, общедоступность, размещение метатега и обработку хоста прокси-сервером/CDN, затем используйте Redo verification.

## 3.4 Развертывание Self-Hosted

Создайте запись сервиса Self-Hosted и выполните утверждённую для вашей среды процедуру развёртывания. Установка нативной версии Server Security — отдельное действие в таблице серверов.

14. Выберите Install для целевого сервера.

15. В разделе 1. Choose a native package выберите операционную систему и архитектуру, соответствующие серверу.

16. В разделе 2. Download and install выберите Download .deb или Download .rpm.

Используйте имя файла, команду установки и значение SHA-256, отображаемые в вашей панели. Типичные команды выглядят следующим образом:



> **Целостность пакета**
> Для пакетов RPM не отключайте проверку подписи и следуйте утвержденной процедуре работы с ключами подписи. Не получайте ключи подписи из неутвержденных источников и не обходите проверку пакетов.

## 4.2 Регистрация сервера в системе

18. В диалоговом окне установки откройте 3. Enroll interactively.

19. На нужном сервере выполните sudo silence-server enroll.

20. Выберите Generate enrollment code.

21. Вводите отображаемый код только в запросе регистрации на нужном сервере.

22. Не закрывайте диалоговое окно установки во время выполнения этапов подготовки.

> **Безопасность кода регистрации**
> Коды регистрации одноразовые, действуют не более 15 минут и никогда не должны копироваться в заявки, документацию, чаты или историю командной оболочки.

Во время подготовки в диалоговом окне могут отображаться такие этапы, как Enrollment in progress, Verified release ready, Installing security stack, Installing core protection, Core check completed, Installing sensors и Installation complete.

## 4.3 Восстановление и повторная регистрация

Для зарегистрированного сервера откройте **Setup / recovery** и используйте **Re-enroll server** или **Generate recovery code** для нужного сервера. Во время восстановления сохраняйте независимый административный доступ.

## 4.4 Подтверждение защиты

23. Выберите Open Security для сервера.

24. Откройте Overview и выберите Refresh.

25. Проверьте Server protection, Provisioning, Sensor health и Guard access security.

26. Убедитесь, что текущее состояние и последние данные телеметрии соответствуют ожидаемой защите.

> **Ожидание активации**
> Если в Policy отображается Saved · pending activation, конфигурация сохранена, но ее пока нельзя считать активной.

# 5. Состояния защиты

| **Состояние**          | **Значение**                                                                                                      | **Что делать**                                                               |
|------------------------|-------------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------|
| ACTIVE                 | Основная защита доступна согласно отчету.                                                                         | Отдельно проверьте состояние дополнительных датчиков и политик.              |
| DEGRADED               | Основная защита может оставаться доступной, но один или несколько показателей работоспособности или покрытия требуют внимания. | Прочтите причину и проверьте Sensors.                          |
| FAILED                 | При подготовке или работе основной защиты произошел сбой.                                                         | Прочтите сообщение об ошибке и следуйте инструкциям по устранению неполадок. |
| PENDING                | Установка, подготовка или активация политики не завершена.                                                        | Дождитесь завершения; не считайте изменение активным.                        |
| CONFIGURATION REQUIRED | Панели нужны дополнительные сведения для подтверждения работоспособности основной защиты.                         | Подтвердите регистрацию и выполните отображаемое требование.                 |
| REMOVED                | Нативная защита удалена или больше не отображается в отчетах.                                                     | Используйте поддерживаемую процедуру Setup / recovery, если она доступна.    |

На карточках датчиков могут отдельно отображаться состояния Healthy, Degraded, Failed, Disabled, Unsupported, Needs configuration, Telemetry stale или No telemetry.

# 6. Настройка MFA и защищенного доступа

## 6.1 MFA учетной записи

При регистрации откройте **Set up 2FA**, отсканируйте QR-код или введите секрет в приложение-аутентификатор, укажите текущий шестизначный код и нажмите **Verify and finish**. При следующих входах используйте актуальный код. Если доступ к аутентификатору потерян, воспользуйтесь сохранённым резервным кодом или утверждённой в вашей организации процедурой восстановления учётной записи. Не передавайте QR-код, секрет и коды восстановления другим лицам.

## 6.2 MFA для доступа к серверу (SSH 2FA / Port Guard)

**SSH 2FA** защищает настроенные TCP-порты, а не только SSH-порт 22. Во время изменения доступа сохраняйте независимый сеанс администратора.

1. В таблице серверов откройте редактирование и укажите защищённые **TCP ports** в **Agent configuration**.
2. В строке сервера выберите **SSH 2FA** и отсканируйте QR-код либо введите **Manual entry key** в приложении-аутентификаторе.
3. Надёжно сохраните восемь **Backup / Recovery Codes**: каждый код одноразовый.
4. Выберите **Next — Verify Code**, введите текущий шестизначный код, нажмите **Verify** и завершите настройку.
5. Повторно откройте **Agent configuration** и проверьте выбранные порты и параметр доступа.

## 6.3 Аутентификация с помощью Port Guard

Откройте адрес **Port Guard**, предоставленный для вашего развёртывания, из той же сети, что и клиент защищённого сервиса. Введите текущий код приложения-аутентификатора или один неиспользованный резервный код, нажмите **Unlock Ports** и повторно подключитесь к сервису. Ориентируйтесь на время доступа, показанное на странице. Учётные данные самого сервиса по-прежнему необходимы.

## 6.4 Отключение или сброс MFA для доступа к серверу

Чтобы отключить MFA для доступа к серверу, выключите **Enable 2FA for access** и сохраните настройку. Чтобы изменить область действия MFA, измените или удалите настроенные защищённые порты и сохраните настройку. Сохраните рабочий сеанс администратора и независимый способ восстановления доступа. После применения изменения агентом проверьте состояние в панели и доступ к целевому серверу. Если работающий сервер не использует сохранённую настройку, обратитесь к ответственному администратору. Не удаляйте файлы или службы вручную.

# 8. Анализ инцидентов и ответных действий

**Разные действия:** **Shut down session** отключает существующее соединение; **Blacklist IP address** сохраняет постоянный запрет новых соединений в своей области. Автоматическая реакция может быть временной и подчиняться другим правилам. Запрос или сохранение не подтверждает отключение либо применение.

## 8.1 Инциденты

Выберите инцидент, чтобы открыть Incident details. Проверьте серьезность, сводку, сведения об источнике, если они доступны, Timeline, Evidence и Technical details.

| **Действие**       | **Результат**                                                        |
|--------------------|----------------------------------------------------------------------|
| Mark investigating | Изменяет состояние проверки инцидента, указывая на активное расследование. |
| Resolve            | Указывает, что проверка инцидента завершена.                         |
| Dismiss            | Указывает, что дальнейшая работа с инцидентом не планируется.        |

> **Состояние инцидента — не устранение последствий**
> Изменение состояния проверки инцидента само по себе не удаляет вредоносное ПО, не прекращает действия злоумышленника и не восстанавливает скомпрометированный сервер.

## 8.2 Ответные действия

| **Состояние**                                      | **Значение**                                                                  |
|----------------------------------------------------|-------------------------------------------------------------------------------|
| REQUESTED / OBSERVED / SHADOW_APPROVED / APPROVED  | Действие зарегистрировано или одобрено для оценки; применение не подтверждено. |
| APPLIED                                            | Ответное действие зарегистрировано как примененное в отображаемой области.    |
| EXPIRED                                            | Временное ответное действие больше не активно.                                |
| REVOKED                                            | Ответное действие отозвано.                                                    |
| FAILED                                             | Запрошенное действие не завершилось успешно.                                  |
| SUPPRESSED                                         | Ответное действие не применялось согласно соответствующей политике.           |

Рассматривайте источник, действие и область, причину, состояние, время начала и истечения вместе. Блокировка новых подключений не обязательно прекращает уже установленное соединение.

# 9. Настройка политики безопасности

## 9.1 Режим автоматического реагирования

| **Режим** | **Поведение**                                                                                                     |
|-----------|-------------------------------------------------------------------------------------------------------------------|
| Observe   | Регистрирует подходящие решения без автоматического применения.                                                   |
| Shadow    | Оценивает подходящие обнаружения без применения временных блокировок.                                             |
| Enforce   | Может применять одобренные временные блокировки IP, когда активны политика и условия обнаружения.                |

Обычный начальный режим после установки — Shadow. Чтобы использовать Enforce, выберите Enforce, просмотрите Enable automatic enforcement? и подтвердите действие с помощью Enable Enforce. Enforce применяется только к подходящим обнаружениям.

## 9.2 Доверенные IP-адреса

42. Откройте Policy → Trusted IPs.

43. Введите Trusted IP or CIDR и, при необходимости, Description.

44. Выберите Add trusted source.

45. Используйте Remove для удаления записи или Move to block для преобразования ее в явную блокировку.

Trusted IPs освобождает источник от подходящих автоматических блокировок. Это не позволяет обходить MFA, ограничения по странам, Allowed IPs / CIDRs, учетные данные сервисов и другие средства управления доступом.

## 9.3 Разрешенные IP-адреса и CIDR

46. Нажмите значок карандаша/редактирования в строке сервера.

47. В Agent configuration введите отдельные адреса IPv4/IPv6 или диапазоны CIDR в поле Allowed IPs / CIDRs (через запятую).

48. Выберите Save и снова откройте диалоговое окно, чтобы убедиться, что панель сохранила значение.

Если сохраненный список пуст, проверка адреса Port Guard позволяет всем источникам перейти к аутентификации. Если список не пуст, продолжить могут только соответствующие адреса или диапазоны.

## 9.4 Явные блокировки

49. Откройте Policy → Explicit blocks.

50. Введите Blocked IP or CIDR, обязательное значение Reason и необязательное Explicit block expiry.

51. Выберите Add explicit block.

52. Используйте Remove для удаления записи. Чтобы исправить запись, удалите ее и создайте новую.

> **Не допускайте блокировки администратора**
> Перед добавлением блокировки проверьте адреса администраторов, мониторинга, NAT и общие адреса, которые могут использовать тот же исходный IP-адрес или CIDR.

## 9.5 Датчики и Suricata

В Policy → Sensor state могут отображаться переключатели Inventory, File Integrity, Security Configuration, YARA-X, CrowdSec, Falco и Suricata.

Для Suricata откройте Policy → Suricata monitored interface, выберите отображаемый вариант или введите проверенный интерфейс, например ens3, затем выберите Save interface. После изменения убедитесь, что поступает актуальная телеметрия Suricata.

# 10. Сетевой доступ, глобус и активные соединения

Откройте **Network access** и выберите управляемый сервер и защищённый TCP-порт. На глобусе и в списке соединений просматривайте данные выбранного сервера и порта: исходные IP-адреса, страны, порты и сведения о сеансах.

Во вкладке **Countries** выберите режим чёрного или белого списка и настройте страны для выбранного порта. Во вкладке **IP addresses** управляйте серверными списками **Always Block** и **Always Allow**. Запись Always Allow не заменяет MFA и аутентификацию защищённого сервиса.

Для действия с соединением откройте его меню и выберите **Shut down session** или **Blacklist IP address**. После действия проверьте отображаемый результат и состояние политики. Сохранённое изменение или поставленный в очередь запрос считайте завершённым после сообщения о применении.

# 11. Просмотр датчиков, инвентаризации, состояния и результатов

Откройте **Sensors** и проверьте состояние каждого датчика и время последнего сигнала. В **Inventory** используйте **Search packages** для просмотра сведений о пакетах. В **Posture** изучите результаты проверки конфигурации и показанные рекомендации. При интерпретации результатов учитывайте время наблюдения.

# 12. Мониторинг событий и телеметрии

Откройте **Events** для просмотра телеметрии сервера. Используйте фильтры датчика, точного типа события и серьёзности, а также **Previous** и **Next** для перехода между страницами. Проверяйте источник, доказательства, серьёзность, время и связанный инцидент, если он указан. Перед выводами по старым результатам обновите представление.

# 13. Устранение неполадок

Если действие не завершилось, проверьте выбранный сервер и порт, показанные в консоли состояние и время, а также текст ошибки. Исправьте входные данные или проблему соединения и повторите нужное действие. При изменении правил доступа сохраняйте независимый сеанс администратора. Для восстановления доступа к аккаунту или серверу используйте утверждённую в вашей организации процедуру.
