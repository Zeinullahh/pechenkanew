# Руководство пользователя Unified Email Platform

Unified Email Platform объединяет три самостоятельных продукта:

- **CMC / Silence 365 Email Visualizer** — настройка почтового домена, визуализация почтовых потоков, просмотр угроз и управление организацией;
- **Email Protector** — защищённая веб-почта с классификацией сообщений, проверкой вложений, папками, настройками и миграцией почты;
- **WebSOC / AI-SOC Web** — подключение веб-доменов к защитному шлюзу, мониторинг трафика, географические ограничения и управление балансом.

Внешний вид и набор доступных функций зависят от роли пользователя, тарифа и настроек организации. Адреса трёх консолей предоставляет администратор организации. Не используйте адрес одной консоли для входа в другую.

## 1. О платформе

### 1.1 Какой продукт использовать

| Задача | Продукт |
|---|---|
| Добавить почтовый домен и настроить MX, SPF, DKIM и DMARC | CMC |
| Посмотреть направления почтовых потоков и категории угроз | CMC |
| Управлять сотрудниками, подразделениями и корпоративными почтовыми серверами | CMC, роль администратора |
| Читать, отправлять и организовывать письма | Email Protector |
| Проверить классификацию письма или результат проверки вложения | Email Protector |
| Перенести письма из другого почтового сервиса | Email Protector |
| Подключить веб-домен к защитному шлюзу | WebSOC |
| Посмотреть RPS, пропускную способность, активные IP-адреса и географию трафика | WebSOC |
| Ограничить веб-трафик по странам или разрешённым портам | WebSOC |

### 1.2 Роли и права доступа

| Роль | Основные возможности |
|---|---|
| Пользователь почты | Работа с собственными письмами, папками и персональными настройками |
| Администратор организации | Управление сотрудниками, подразделениями, доменами, общими подписями и настройками защиты |
| Администратор домена | Настройка DNS и почтовых серверов, проверка статусов домена |
| Администратор WebSOC | Подключение веб-доменов, изменение origin-адреса и списка стран |
| Сотрудник платформы | Управление согласованными ценами клиентов; этот раздел недоступен обычным клиентам |

Если нужный пункт отсутствует или отображается сообщение об отказе в доступе, обратитесь к администратору организации. Не используйте чужую учётную запись для обхода ограничений.

### 1.3 Что потребуется перед началом

В зависимости от задачи подготовьте:

- адрес нужной консоли;
- рабочую учётную запись;
- приложение-аутентификатор для 2FA;
- доступ к DNS-панели домена;
- права на изменение сайта и DNS для подключения WebSOC;
- адрес или имя исходного веб-сервера для WebSOC;
- данные внешнего почтового ящика или разрешение Microsoft для миграции;
- платёжные полномочия, если требуется пополнение баланса.

> Важно: значения DNS, IP-адреса, ключи подтверждения и суммы всегда берите из своей консоли. Не копируйте значения из примеров или чужих инструкций.

## 2. Доступ к учётной записи

### 2.1 Общие правила входа

У каждой консоли собственный экран входа и собственная сессия. Если в организации включён единый вход, консоль автоматически перенаправит вас на страницу **AI-CSD** или покажет кнопку **Войти через AI-CSD / Sign in**.

1. Откройте адрес продукта, предоставленный администратором.
2. Выберите доступный способ входа.
3. Завершите подтверждение у поставщика учётной записи, если используется единый вход, Google или Microsoft.
4. Введите шестизначный код, если открылась страница 2FA.
5. После входа убедитесь, что в профиле указана ожидаемая учётная запись.

### 2.2 Доступ к CMC

CMC может показывать следующие способы входа:

- **Sign in** по email и паролю;
- **Continue with Google**;
- **Continue with Outlook**;
- **Войти через AI-CSD / Sign in**, если включён единый вход.

Для создания клиентской учётной записи:

1. На экране входа выберите **Create account**.
2. Выберите **Monthly** или **Yearly**.
3. Выберите доступный план. Названия, ограничения и цены берите с текущего экрана.
4. Укажите имя пользователя и email.
5. Нажмите кнопку отправки кода подтверждения рядом с email.
6. Введите полученный код и пароль.
7. При наличии промокода введите его до завершения регистрации.
8. Завершите регистрацию и войдите в CMC.

Для локальной учётной записи CMC предложит настроить 2FA:

1. На странице **Set Up Two-Factor Authentication** отсканируйте QR-код приложением-аутентификатором.
2. Если сканирование недоступно, выберите **Can't scan? Enter key manually** и добавьте показанный ключ вручную.
3. Введите шестизначный код.
4. Нажмите **Activate 2FA**.

При последующих входах введите код на странице **Two-Factor Authentication** и нажмите **Verify**.

### 2.3 Доступ к Email Protector

Email Protector может автоматически открыть единый вход или показать:

- **Continue with Google**;
- **Continue with Microsoft**;
- поля **Email** и **Password** с кнопкой **Sign in**;
- **Login with QR Code**.

Локальные учётные записи обычно создаёт администратор организации. При первом входе система может потребовать:

1. изменить временный пароль;
2. настроить 2FA;
3. подтвердить вход шестизначным кодом.

Для входа по QR-коду выберите **Login with QR Code**, отсканируйте показанный код на втором авторизованном устройстве и подтвердите вход на странице подтверждения.

### 2.4 Доступ к WebSOC

Для регистрации в WebSOC:

1. На странице **Welcome** выберите **Register**.
2. Заполните **Email** и **Username**.
3. Введите пароль и повторите его в **Confirm password**.
4. При необходимости укажите **Recovery password**, **Recovery email** и **Promocode**.
5. Подтвердите возраст и согласие с условиями использования.
6. Нажмите **Continue**.
7. На странице **Set up 2FA** отсканируйте QR-код или введите секретный ключ вручную.
8. Введите **6-digit code** и нажмите **Verify and finish**.

Пароль WebSOC должен содержать хотя бы одну заглавную латинскую букву и одну цифру и состоять из латинских букв и цифр. Те же требования применяются к recovery password, если он указан.

Для обычного входа:

1. Выберите **Log in**.
2. Введите **Email or Username** и **Password**.
3. Нажмите **Continue**.
4. Введите код на странице **Two-factor authentication**.
5. Нажмите **Verify and continue**.

Для восстановления пароля выберите **Forgot password?**, запросите код на email, затем укажите код и новый пароль. Кнопка **Resend code** отправляет код повторно.

## 3. CMC — Silence 365 Email Visualizer

### 3.1 Первоначальная настройка

Для самостоятельной клиентской учётной записи CMC сначала требуется выбрать план, затем завершить мастер **Первичная настройка доменной почты**.

Мастер состоит из четырёх этапов:

1. **Домен**;
2. **Проверка DNS**;
3. **Безопасность**;
4. **Готово**.

Прогресс сохраняется для домена. Если вы вернётесь позже, мастер продолжит с текущего этапа.

Если организация использует только Google или Outlook и на экране доступен вариант **Use AI-SOC as security layer (Gmail/Outlook only)**, можно продолжить без настройки собственной доменной почты. Используйте этот вариант только после согласования с администратором домена.

### 3.2 Добавление и подтверждение домена

1. На этапе **Шаг 1. Добавьте домен** введите доменное имя без `https://` и без пути.
2. Нажмите **Продолжить**.
3. На этапе **Шаг 2. Подтвердите домен через DNS** скопируйте показанные **TXT имя** и **TXT значение**.
4. Создайте TXT-запись в DNS-панели домена.
5. Дождитесь распространения DNS.
6. Нажмите **Проверить сейчас**. Мастер также выполняет периодическую проверку.
7. Продолжайте только после появления статуса **Подтверждён** или **Verified**.

Некоторые DNS-панели автоматически добавляют доменное имя к полю Name. Следуйте подсказке непосредственно в CMC, чтобы не получить повторяющийся суффикс домена.

### 3.3 Настройка MX, SPF, DKIM и DMARC

На этапе **Шаг 3. Настройка безопасности** CMC показывает точные DNS-записи, которые необходимо добавить.

| Запись | Назначение |
|---|---|
| MX | Направляет входящую почту на нужный почтовый сервер |
| SPF | Указывает источники, которым разрешено отправлять почту от имени домена |
| DKIM | Публикует ключ для проверки подписи исходящих писем |
| DMARC | Задаёт политику для писем, не прошедших SPF или DKIM, и адреса отчётов |

Для каждой записи:

1. Нажмите кнопку генерации записи, если она отображается.
2. Скопируйте значения **Тип**, **Имя/Host**, **Значение**, **Приоритет** и **TTL** точно в том виде, в котором они показаны.
3. Создайте или обновите запись в DNS-панели.
4. Дождитесь распространения DNS.
5. Нажмите **Проверить**.
6. Убедитесь, что статус изменился на **Настроено** или **Configured**.

Для DMARC укажите алиасы RUA и RUF, если мастер их запрашивает. Они определяют адреса для агрегированных отчётов и отчётов об ошибках.

> Важно: перед изменением существующей SPF-записи согласуйте итоговое значение с администратором почты. Несколько отдельных SPF-записей для одного имени могут нарушить проверку отправителя.

Статусы мастера:

| Статус | Что означает |
|---|---|
| **Не настроено** | Требуемая запись не найдена |
| **Нужно обновить** | Найденное значение отличается от рекомендуемого |
| **Настроено** | Запись найдена и соответствует ожидаемому значению |
| **Ожидает подтверждения** | Изменение ещё не обнаружено |
| **Ошибка** | Проверку завершить не удалось |

После настройки всех записей перейдите на этап **Шаг 4. Готово** и нажмите **Перейти в панель**.

### 3.4 Управление доменами

Администратору доступны разделы **Домены** и **Управление доменами**.

В них можно:

- добавить домен;
- скопировать токен подтверждения;
- повторить **Verify**;
- посмотреть отдельные статусы MX, SPF, DKIM и DMARC;
- назначить домен основным через **Set default**;
- указать разрешённые IP-адреса SMTP-серверов;
- открыть **DNS-настройка** для продолжения мастера;
- переименовать или удалить домен.

Перед удалением домена убедитесь, что он не используется сотрудниками и почтовыми клиентами. Удаление подтверждается отдельно.

### 3.5 Панель и визуализация почтовых потоков

На главной панели CMC отображается граф почтовых связей. Узлы представляют сотрудников, подразделения или домены, а связи — почтовый обмен.

Основные элементы:

- **Входящие** — письма, поступившие в организацию;
- **Исходящие** — письма, отправленные из организации;
- **Временной интервал** — период данных;
- **Фильтр** — уточнение по отправителю, получателю, теме, тексту и вложениям;
- карточки аналитики по подразделениям и доменам.

Чтобы исследовать поток:

1. Выберите **Входящие** или **Исходящие**.
2. Нажмите **Временной интервал**.
3. Выберите последний час, 3, 6, 12 или 24 часа, всё время либо пользовательский диапазон.
4. При необходимости откройте **Фильтр**, заполните нужные поля и нажмите **Применить фильтры**.
5. Нажмите на узел графа, чтобы открыть связанные письма.
6. Используйте поиск и сортировку **Сначала новые** / **Сначала старые** в списке писем.
7. Откройте письмо для просмотра содержимого, заголовков и вложений.

Пользовательский диапазон не должен заканчиваться в будущем, а время начала должно быть раньше времени окончания.

### 3.6 Категории угроз

Кнопка со стрелкой внизу панели открывает **Категории угроз**.

| Категория | Значение для пользователя |
|---|---|
| **Possibly spoofed** | Отправитель или домен могут быть подменены |
| **Spam** | Сообщение похоже на нежелательную рассылку |
| **Dangerous link** | В сообщении обнаружена потенциально опасная ссылка |
| **Possibly phishing** | Сообщение может пытаться получить учётные или платёжные данные |
| **Malware in the attachment** | Во вложении обнаружен опасный объект |
| **Secure emails** | Проверки не выявили известных признаков угрозы |

Нажмите карточку категории, затем **Нажмите, чтобы посмотреть**, чтобы открыть письмо. В подробном просмотре доступны отправитель, получатель, дата, содержимое, исходный текст и сведения о вложениях.

Статусы вложений:

- **Безопасно** — проверка завершена без обнаружения угроз;
- **Подозрительно** — требуется осторожность и дополнительная проверка;
- **Обнаружено вредоносное ПО** — вложение нельзя считать безопасным;
- **Ожидает проверки** — дождитесь завершения анализа.

Перемещение письма в корзину и **Удалить навсегда** — разные действия. Постоянное удаление используйте только после проверки выбранного письма.

### 3.7 Сотрудники и администраторы

Раздел **Сотрудники** доступен администраторам.

Чтобы добавить сотрудника вручную:

1. Откройте **Настройки** → **Сотрудники**.
2. Нажмите **+ Добавить** → **Создать вручную**.
3. Укажите email, имя, фамилию и другие необходимые данные.
4. Проверьте показанный способ входа: Google, Microsoft или внутренняя учётная запись.
5. При необходимости добавьте дополнительные адреса, телефоны и алиасы.
6. Нажмите **Создать**.

Для массового добавления выберите **Загрузить список сотрудников**, скачайте **Скачать шаблон CSV**, заполните его без изменения структуры и запустите **Импорт**. После обработки проверьте значения **Создано** и **Пропущено**.

В меню сотрудника доступны подтверждённые действия:

- **Редактировать**;
- **Изменить пароль** для внутренней учётной записи;
- **Редактировать алиасы**;
- **Сделать администратором** или **Отозвать права администратора**;
- **Удалить**.

Выдавайте права администратора только пользователям, которым действительно необходимо управлять организацией.

### 3.8 Подразделения

Администратор может создавать подразделения и назначать в них сотрудников.

1. Откройте **Настройки** → **Подразделения**.
2. Создайте подразделение и укажите уникальное название.
3. Откройте список участников подразделения.
4. Добавьте сотрудников из доступного списка.
5. Для исключения сотрудника используйте действие удаления из состава подразделения.

Удаление подразделения не следует выполнять, пока его состав и влияние на визуализацию не проверены.

### 3.9 Общие настройки защиты

Вкладка **Безопасность** доступна администраторам и может содержать:

- **Включить детектор фишинга**;
- **Включить проверку вложений на вирусы**;
- **Управление блокировками** для доменов и адресов;
- переход к настройкам корпоративных почтовых серверов.

После изменения переключателя дождитесь завершения сохранения и убедитесь, что новое положение сохранилось.

### 3.10 Корпоративные почтовые серверы

Раздел **Company Email Servers** предназначен для администратора.

1. Укажите **IMAP server**, **IMAP port** и **IMAP security** для входящей почты.
2. При необходимости укажите **SMTP server**, **SMTP port** и **SMTP security** для исходящей почты.
3. Для защищённого соединения выбирайте **SSL/TLS** или **STARTTLS** в соответствии с настройками сервера.
4. Нажмите кнопку сохранения.
5. Проверьте панель с итоговыми параметрами для пользователей почтовых клиентов.

Если SMTP не указан, внешние клиенты смогут получать почту по IMAP, а отправка останется доступной только в веб-приложении.

> Важно: вариант **None / plain text** передаёт данные без защиты канала. Используйте его только в изолированной доверенной сети и по решению администратора безопасности.

### 3.11 Настройки организации и AI

Во вкладке **Общие** можно выбрать язык, часовой пояс и, при наличии прав, изменить название и логотип организации.

Вкладка **AI Agent** позволяет администратору настроить общий AI-помощник для сотрудников. Если она доступна:

1. Выберите поставщика и модель.
2. Укажите endpoint только для поддерживаемой конфигурации.
3. Введите ключ доступа в защищённом месте.
4. Сохраните настройки.
5. Выполните встроенную проверку соединения, если она предлагается.

Не отправляйте ключ доступа сотрудникам и не публикуйте его в снимках экрана.

### 3.12 Тариф, кошелёк и платежи

Меню профиля показывает **Balance**, **Top Up Balance** и **Manage Plan**.

Для пополнения:

1. Откройте профиль и выберите **Top Up Balance**.
2. Проверьте валюту, минимальную и максимальную сумму на экране.
3. Введите сумму.
4. Нажмите **Оплатить / Pay**.
5. Завершите оплату на защищённой странице платёжного сервиса.
6. После возврата проверьте обновлённый баланс.

Для смены тарифа:

1. Выберите **Manage Plan**.
2. Сравните лимиты пользователей, администраторов, хранилища и доступных AI-операций.
3. Выберите месячный или годовой цикл.
4. Выберите тариф и проверьте стоимость активации или перехода.
5. Подтвердите действие.

Цены и валюта зависят от развёртывания и условий клиента. Используйте только значения, отображаемые в вашей консоли.

## 4. Email Protector

### 4.1 Основные области интерфейса

После входа открывается **Email Protector**. Интерфейс состоит из:

- левой панели папок;
- списка писем;
- области чтения и сведений о безопасности;
- кнопки **Написать**;
- поиска;
- переключателя аккаунтов;
- кнопки **Настройки**;
- меню языка и выхода.

В системной части могут отображаться **Все письма**, **Важные**, **Входящие**, **Отправленные**, **Черновики**, **Запланированные** и **Корзина**. Раздел безопасности содержит доступные для организации папки карантина и ошибок. Пользовательские папки находятся в разделе **Мои папки**.

### 4.2 Чтение и проверка письма

1. Выберите папку.
2. Нажмите письмо в списке.
3. Проверьте отправителя, получателей, тему и дату.
4. Посмотрите цветовой индикатор и классификацию безопасности.
5. Раскройте **Вложения** и проверьте статус каждого файла.
6. При необходимости нажмите **Показать детали** или **Показать исходный текст**.

Основные классификации:

| Классификация | Рекомендуемое действие |
|---|---|
| **Безопасные / Secure** | Работайте с письмом как обычно, сохраняя стандартную осторожность |
| **Спам / Spam** | Проверьте отправителя; не отвечайте на нежелательное сообщение |
| **Спуфинг / Possibly Spoofed** | Подтвердите личность отправителя по независимому каналу |
| **Есть угрозы / Possibly Phishing** | Не переходите по ссылкам и не вводите учётные данные |
| Опасные ссылки | Не открывайте ссылку до проверки специалистом |
| Опасные вложения | Не скачивайте и не запускайте файл |

Статусы вложений:

| Статус | Действие |
|---|---|
| **Безопасно / Clean** | Скачивание доступно |
| **Подозрительно / Suspicious** | Изучите детали и обратитесь к администратору при сомнении |
| **Загрузка заблокирована / Download blocked** | Не пытайтесь получить файл обходным способом |
| **Проверка… / Scanning…** | Дождитесь завершения |
| **Не проверено / Not scanned** | Не открывайте файл без дополнительной проверки |

Наличие статуса **Безопасно** не отменяет проверку контекста письма, адреса отправителя и ожидаемости вложения.

### 4.3 Поиск и работа со списком

- Введите текст в поле **Поиск писем...**.
- Используйте фильтры **Все**, **Безопасные**, **Спам**, **Спуфинг** и **Есть угрозы**.
- Нажмите звезду, чтобы добавить письмо в **Важные**.
- Используйте меню папки, чтобы переместить письмо в пользовательскую папку или вернуть во **Входящие**.
- Отметьте несколько писем флажками для массового перемещения в корзину.
- В **Корзине** выберите **Восстановить** или постоянное удаление.
- Нажмите **Загрузить ещё**, если показана только часть списка.

> Важно: постоянное удаление нельзя отменить. Сначала убедитесь, что выбрана именно **Корзина** и нужные сообщения.

### 4.4 Создание и отправка письма

1. Нажмите **Написать**.
2. Заполните **Кому**. При необходимости раскройте **Копия** и **Скрытая копия**.
3. Укажите тему и текст.
4. Добавьте файлы кнопкой вложения.
5. Чтобы отправить позже, выберите **Запланировать отправку** и укажите будущие дату и время.
6. Нажмите **Отправить письмо**.

Черновик можно открыть из папки **Черновики**, отредактировать и отправить. Запланированные письма доступны в **Запланированные**; до отправки их можно просмотреть и отменить через соответствующее действие интерфейса.

### 4.5 Действия с открытым письмом

Для открытого письма доступны, в зависимости от сообщения и прав:

- отметить или снять отметку **Важные**;
- открыть полный просмотр;
- переместить в папку;
- показать исходный текст;
- перевести и вернуться к оригиналу;
- создать AI-черновик ответа;
- отписаться от рассылки, если письмо содержит поддерживаемую ссылку;
- переместить в корзину.

Перед отпиской проверьте отправителя. Не используйте ссылку отписки в явно фишинговом письме.

### 4.6 Пользовательские папки и правила

Правила исключения имеют приоритет над правилами включения. Через меню папки её можно переименовать, изменить правила или удалить. Перед удалением проверьте предупреждение на экране.

### 4.7 Переключение аккаунтов

5. Для переключения выберите нужную учётную запись в списке.

Активную учётную запись удалить из списка нельзя. Для локальной записи при переключении может потребоваться повторный ввод пароля.

## 5. WebSOC / AI-SOC Web

### 5.1 Подключение домена

В WebSOC объект подключения называется агентом, но пользовательский мастер настраивает домен и исходный веб-сервер. Устанавливать программу по непроверенной команде не требуется.

1. Откройте **Выбор источника данных**.
2. Нажмите **Добавить нового агента** или **Зарегистрировать нового агента**.
3. В поле **Домен** укажите защищаемый домен.
4. В поле **IP-адрес** укажите текущий origin host или IP исходного сервера.
5. Нажмите **Зарегистрировать**.

После регистрации откроются три шага подключения.

#### Шаг 1. Подтверждение владения сайтом

1. В блоке **Step 1. Add ownership meta tag on your origin website** нажмите **Copy tag**.
2. Добавьте показанный meta-тег в раздел `<head>` главной страницы origin-сайта.
3. Опубликуйте изменение.
4. Убедитесь, что страница доступна извне по доменному имени.

Кнопка **Copy key** копирует только значение ключа; **Copy tag** — готовый тег.

#### Шаг 2. Делегирование ACME

1. В блоке **Step 2. Add ACME delegation CNAME** скопируйте **Name** и **Hostname (target)**.
2. Создайте CNAME-запись в DNS-панели.
3. Сохраните запись и дождитесь распространения DNS.
4. Нажмите **Verify ownership and DNS**.

Успешный результат отображается как **Ownership and DNS verified**. На этом этапе маршрутизация трафика ещё может быть не активна.

#### Шаг 3. Переключение трафика

После успешной проверки появится блок **Step 3. DNS A record to add (switch traffic through WebSOC)**.

1. Скопируйте показанные **Name** и **IP address**.
2. Убедитесь, что origin-адрес в WebSOC указан правильно и приложение отвечает на разрешённом порту.
3. Создайте или обновите A-запись домена указанным значением.
4. Дождитесь распространения DNS.
5. Откройте **Domain setup details** и проверьте **DNS routing**.

> Важно: изменение A-записи переключает пользовательский трафик. Выполняйте его в согласованное окно изменений и сохраняйте доступ к DNS и origin-серверу для восстановления.

### 5.2 Статусы домена

| Статус | Значение |
|---|---|
| **Delegation not verified** | Meta-тег или CNAME ещё не подтверждены |
| **Delegation verified / DNS pending** | Владение и делегирование подтверждены, но A-запись ещё не направляет трафик через WebSOC |
| **Active** | Делегирование подтверждено и DNS-маршрутизация активна |

Кнопка с круговой стрелкой повторяет проверку. Кнопка документа открывает **Domain setup details** со всеми требуемыми значениями.

### 5.3 Настройка origin-сервера

1. В **Выбор источника данных** найдите домен.
2. Нажмите значок карандаша.
3. В **Конфигурация агента** проверьте **IP-адрес** origin-сервера.
4. Укажите новый origin host или IP-адрес.
5. Нажмите **Сохранить**.
6. Дождитесь сообщения **Конфигурация успешно обновлена!**.

Перед сменой origin-адреса убедитесь, что новый адрес доступен и обслуживает нужный домен.

### 5.4 Выбор доменов и карта трафика

1. Нажмите **Выбор источника данных**.
2. Установите флажки рядом с доменами, которые нужно анализировать.
3. В правой части панели выберите параметр:
   - **RPS** — запросы в секунду;
   - **Пропускная способность / Bandwidth** — объём передаваемых данных;
   - **Активные пользователи / Active Users** — число активных IP-адресов.
4. Наведите указатель на страну на глобусе, чтобы посмотреть данные по выбранным доменам.

Цветовая интенсивность карты сравнивает страны по выбранному параметру. Для оценки тенденции используйте график, а не только текущий цвет.

### 5.5 Графики и лидирующие страны

Нажмите стрелку внизу экрана, чтобы открыть **График нагрузки сервера**.

Доступны периоды:

- **1 day**;
- **2 days**;
- **7 days**;
- **14 days**;
- **1 month**;
- **3 months**.

В этом окне также отображаются:

- страны с наибольшим числом активных IP-адресов;
- страны с наибольшей пропускной способностью;
- страны с наибольшим RPS.

Выделение участка графика уточняет период для связанных показателей. Сравнивайте одинаковые домены и интервалы, чтобы избежать неверных выводов.

### 5.6 Уведомления об аномалиях

При обнаружении аномалии вверху экрана появляется красная панель с сообщением. Прочитайте текст, зафиксируйте домен и время, затем нажмите **OK**, чтобы закрыть уведомление.

Закрытие панели подтверждает только просмотр сообщения и не означает устранение причины. Проверьте графики и origin-сервис, а при необходимости передайте сведения администратору безопасности.

### 5.7 Чёрный список стран

1. Нажмите **Черный список стран**.
2. Откройте вкладку **Не в черном списке** или найдите страну через поиск.
3. Выберите страну и нажмите **Добавить**.
4. Проверьте, что она появилась во вкладке **В черном списке**.

Для отмены выберите страну во вкладке **В черном списке** и нажмите **удалить**.

> Важно: перед добавлением страны проверьте, не находятся ли там сотрудники, клиенты, внешние службы мониторинга или платёжные системы. Сохраните административный доступ из разрешённой страны.

### 5.8 Язык и тема

Откройте меню в левом верхнем углу. В нём доступны:

- **Стиль глобуса**;
- **Выбрать язык**;
- **История платежей**;
- **Промокод**.

### 5.9 Баланс и платежи

Баланс отображается в меню профиля.

Для пополнения:

1. Откройте профиль.
2. Нажмите **Пополнить баланс**.
3. Введите сумму не ниже минимума, показанного на экране.
4. Нажмите **Создать платеж**.
5. Завершите оплату в защищённом платёжном окне.
6. После возврата дождитесь обновления баланса.

Для просмотра операций откройте меню → **История платежей**.

| Статус | Значение |
|---|---|
| **Завершено** | Средства успешно зачислены |
| **В ожидании** | Платёж ещё обрабатывается |
| **Не удалось** | Платёж не завершён |

Промокод вводится в разделе **Промокод**. Если интерфейс сообщает, что он **Зафиксирован**, изменить значение для этой учётной записи нельзя.

### 5.10 Удаление домена

Значок корзины рядом с доменом удаляет его после подтверждения. Перед этим сохраните сведения, необходимые для возврата DNS на origin, и убедитесь, что домен больше не должен обслуживаться через WebSOC.

## 6. Типовые неполадки

### 6.1 Не удаётся войти

1. Проверьте, что открыта правильная консоль.
2. Убедитесь, что выбран правильный способ входа: единый вход, Google, Microsoft или локальная учётная запись.
3. Проверьте раскладку клавиатуры и адрес email.
4. Для локальной учётной записи используйте восстановление пароля, если оно доступно.
5. Если сообщение говорит об отсутствии разрешения, обратитесь к администратору организации.

### 6.2 Код 2FA отклонён

1. Введите новый код из приложения-аутентификатора; код может успеть смениться.
2. Проверьте автоматическую установку даты и времени на телефоне.
3. Убедитесь, что выбран правильный аккаунт в приложении-аутентификаторе.
4. Не используйте код из SMS, если экран просит код authenticator app.
5. После нескольких неудач прекратите повторные попытки и обратитесь в поддержку.

### 6.3 Не приходит код подтверждения или восстановления

1. Проверьте правильность email.
2. Посмотрите папки спама и карантина.
3. Подождите несколько минут и используйте повторную отправку один раз.
4. Если почта организации фильтрует системные сообщения, обратитесь к почтовому администратору.

### 6.4 Домен CMC ожидает подтверждения

1. Сравните имя и значение TXT-записи с CMC посимвольно.
2. Проверьте, не добавила ли DNS-панель домен к имени повторно.
3. Убедитесь, что запись опубликована в нужной DNS-зоне.
4. Дождитесь распространения DNS и нажмите **Проверить сейчас**.

### 6.5 SPF, DKIM, DMARC или MX не подтверждаются

1. Откройте запись в CMC повторно и сравните тип, имя, значение, приоритет и TTL.
2. Для SPF убедитесь, что в одном имени не созданы конфликтующие записи.
3. Для DKIM проверьте selector и `_domainkey`.
4. Для DMARC проверьте имя `_dmarc` и адреса отчётов.
5. Для MX проверьте целевой хост и приоритет.
6. После исправления дождитесь обновления DNS и нажмите **Проверить**.

### 6.6 Письма или показатели не обновились

1. Нажмите **Обновить**, если кнопка доступна.
2. Проверьте выбранную папку, домен, направление и временной интервал.
3. Очистите слишком узкие фильтры.
4. Проверьте, не выбрана ли другая учётная запись.
5. Повторите попытку после обновления страницы.

### 6.7 Вложение заблокировано

Не отключайте защиту и не просите отправителя переименовать файл для обхода проверки. Передайте администратору:

- имя отправителя;
- тему письма;
- время получения;
- имя файла;
- показанный статус и сведения проверки без содержимого секретных данных.

### 6.8 Миграция почты не подключается

1. Проверьте выбранного поставщика.
2. Для Gmail и iCloud используйте действующий app password.
3. Для Outlook повторно выполните **Connect Outlook Account**.
4. Для **Custom IMAP** проверьте сервер, порт, email и пароль.
5. Если задача поставлена на паузу, нажмите **Resume**.

### 6.9 WebSOC не подтверждает домен

1. Убедитесь, что meta-тег опубликован на доступной странице origin-сайта.
2. Сравните CNAME Name и Hostname с **Domain setup details**.
3. Дождитесь распространения DNS.
4. Нажмите **Verify ownership and DNS** или значок повторной проверки.
5. Если статус уже **Delegation verified / DNS pending**, проверьте A-запись отдельно.

### 6.10 После изменения WebSOC нет доступа

1. Проверьте, не добавлена ли ваша страна в **Черный список стран**.
2. Убедитесь, что origin host или IP указан правильно.
3. Используйте сохранённый административный канал для отмены ошибочного ограничения.

### 6.11 Платёж остаётся в ожидании

1. Не создавайте повторный платёж немедленно.
2. Откройте **История платежей** и проверьте статус операции.
3. Обновите баланс после завершения обработки.
4. Если статус долго не меняется, передайте поддержке время, сумму и ID транзакции. Не отправляйте номер карты, CVC или коды подтверждения.

## 7. Рекомендации по безопасности

- Используйте уникальные пароли и храните их в менеджере паролей.
- Защитите секрет 2FA и устройство с приложением-аутентификатором.
- Никому не передавайте коды подтверждения, recovery password, app password, AI-ключи и токены Calendly.
- Удаляйте секреты со снимков экрана перед отправкой в поддержку.
- Сверяйте DNS-значения с текущей консолью непосредственно перед публикацией.
- Не отключайте детектор фишинга или проверку вложений ради теста.
- Не добавляйте отправителя в доверенные только потому, что письмо выглядит знакомым.
- Проверяйте неожиданные финансовые запросы и смену реквизитов по независимому каналу.
- Предоставляйте права администратора по принципу минимальных привилегий.
- Перед ограничением стран сохраняйте резервный административный доступ.
- Регулярно проверяйте статусы доменов, угроз, вложений, WebSOC и платежей.

## 8. Глоссарий

| Термин | Значение |
|---|---|
| 2FA | Второй фактор входа — одноразовый код из приложения-аутентификатора |
| App password | Отдельный пароль, созданный поставщиком почты для подключения приложения |
| DKIM | Подпись исходящего письма, проверяемая по ключу в DNS |
| DMARC | Политика обработки писем, не прошедших SPF или DKIM, и механизм отчётности |
| DNS | Система записей домена, связывающая имена с сервисами и настройками |
| IMAP | Протокол доступа к почте на сервере |
| MX | DNS-запись, указывающая сервер приёма почты |
| Origin | Исходный веб-сервер, к которому WebSOC направляет разрешённые запросы |
| Quarantine | Изолированная область для подозрительных сообщений |
| RPS | Число веб-запросов в секунду |
| SMTP | Протокол отправки почты |
| SPF | DNS-политика, перечисляющая разрешённые источники отправки почты |
| TTL | Время кэширования DNS-записи |

## 9. Обращение в поддержку

Используйте канал поддержки, предоставленный вашей организацией. Перед обращением подготовьте:

- название продукта: CMC, Email Protector или WebSOC;
- email учётной записи без пароля;
- домен, если проблема связана с доменом;
- дату, точное время и часовой пояс;
- последовательность выполненных действий;
- точный текст видимой ошибки;
- снимок экрана без ключей, токенов, QR-кодов и персональных данных;
- для платежа — сумму, статус и ID транзакции без реквизитов карты;
- для письма — отправителя, тему и время, но не конфиденциальное содержимое без необходимости.

Никогда не отправляйте поддержке пароль, шестизначный код 2FA, секретный ключ, recovery password, полный app password, CVC или приватный AI-ключ.
